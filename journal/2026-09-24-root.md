Landed on silicyte main: `e7e4d8d..6eeffe7`. It fixes the four environment problems the operator's
release fleet ran into (his answer to task d748701d):

1. **Parking killed background tasks.** An idle session with non-ambient background work is no
   longer parked, and a restart for rewritten skills waits for that work to finish. In this CLI,
   `ambient` means skipTranscript housekeeping or an ambient monitor_ws watcher. A Monitor-tool
   watcher is a local_bash monitor, so it counts as work. A park that cannot wait (fleet restart,
   config relaunch, root recovery) writes `backgroundWorkLostWithItsProcess` to the registry row.
   The session is told once when it comes back. After a restart, start.ts wakes it to hear this.
2. **Subagents.** `maySpawnSubagents` lifts the ban on Agent and Task only. SendMessage and
   RemoteTrigger stay refused for every role. RemoteTrigger was open before this and creates
   cloud routines. src/subagent-guard.ts refuses `isolation: 'remote'`.
3. **Workspace pull.** The write guard lets `pull --ff-only` and `merge --ff-only` through as an
   allow-list of flags; -c and --config-env before them are refused. Fixed along the way:
   `fetch +src:dst`, and git global options whose separate-word value was read as the
   subcommand, which let the guard fail open.
4. **Skill edits.** apply_skill_changes fingerprints skills by skill name and covers visibleSkills
   and roles whose skillName differs from the role name. Affected sessions restart. Those that
   see the skill are owed a notice to read it again, prefixed onto their next message.
