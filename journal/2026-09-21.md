# 2026-09-21

## Trello ZaRVnuX8 — the model field becomes a dropdown

Landed `9313c4b..5cec1f8`.

The card read as cosmetic: effort is a `<select>`, model is an `<input>`, make them match. It
was not. The reason for the asymmetry was in the types, not the markup — `EFFORT_LEVELS` names
every effort that exists and **no constant anywhere named a model**. `knownModels` in the
snapshot was `modelsAlreadyInPlay()`: the union of the role config and the live session
records. That describes what is running, not what may be chosen, which is exactly why it was
wired to a `<datalist>` (a suggestion) and not a `<select>` (a constraint). Building a dropdown
straight from it would have made "the models you may pick" equal "the models someone is already
on" — you could never move a session to a model nobody was using, which is the whole point of
retuning one.

So: `MODELS_THE_CODE_KNOWS` in `types.ts`, beside `EFFORT_LEVELS`, from the authoritative model
table (read it, did not recall it — the codebase already disagreed with itself about ids).
`modelsToChooseFrom(inPlay)` = that list plus anything actually in play, deduped. Two things I
decided on purpose and would defend:

- **The names stay `string`, not a union type.** A union would have been the "tighter" move and
  it would have been wrong: the fleet config carries `claude-haiku-4-5-20251001` and would stop
  typechecking, and more importantly a fleet must be able to run a model this code has not
  heard of. The list says what is *offered*, never what is *allowed*.
- **An option that reopens the text input.** Without it the dropdown is a cage that goes stale
  invisibly: nobody notices the list is old until the day they need a model that shipped last
  month, and then the fix is a code change plus a full restart. With it, staleness costs a
  keystroke. ~15 lines for a UI that ages gracefully.

## The hole I walked through on the way

I edited 69KB of JavaScript living inside an HTML file, ran the suite green, and then asked
what would have caught a stray brace. Nothing. The suite opens `app.html` three times and reads
it as **text** every time — `locales-agree` greps for keys, `limit-headline` greps for
declarations, `write-guard` only names the path. A syntax error there is not a broken feature,
it is a blank dashboard, and it would have landed green.

`tests/panel-script.test.ts` now runs `node --check` on the one `<script>`. Notes for next
time: the Function constructor is the short way and eslint refuses it (`no-implied-eval`,
rightly, and a disable comment is impossible here because comments are banned); the temp file
needs a **`.cjs`** extension so it parses in sloppy mode, which is what a plain `<script>`
actually is — `.mjs` would be strict and is the wrong check.
