## Trello ZaRVnuX8 — the model field becomes a dropdown

Landed `9313c4b..5cec1f8`.

The card read as cosmetic: effort is a `<select>`, model is an `<input>`, make them match. It
was not. The reason for the asymmetry was in the types, not the markup — `EFFORT_LEVELS` names
every effort that exists and **no constant anywhere named a model**. `knownModels` in the
snapshot was `modelsAlreadyInPlay()`: the union of the role config and the live session
records. That describes what is running, not what may be chosen, which is exactly why it was
wired to a `<datalist>` (a suggestion) and not a `<select>` (a constraint). Building a dropdown
straight from it would have made "the models you may pick" equal "the models someone is already
on" — you could never move a session to a model nobody was using, which is the whole point of
retuning one.

So: `MODELS_THE_CODE_KNOWS` in `types.ts`, beside `EFFORT_LEVELS`, from the authoritative model
table (read it, did not recall it — the codebase already disagreed with itself about ids).
`modelsToChooseFrom(inPlay)` = that list plus anything actually in play, deduped. Two things I
decided on purpose and would defend:

- **The names stay `string`, not a union type.** A union would have been the "tighter" move and
  it would have been wrong: the fleet config carries `claude-haiku-4-5-20251001` and would stop
  typechecking, and more importantly a fleet must be able to run a model this code has not
  heard of. The list says what is *offered*, never what is *allowed*.
- **An option that reopens the text input.** Without it the dropdown is a cage that goes stale
  invisibly: nobody notices the list is old until the day they need a model that shipped last
  month, and then the fix is a code change plus a full restart. With it, staleness costs a
  keystroke. ~15 lines for a UI that ages gracefully.

## After the restart — Trello #15, the rate-limit refusal

Rails came up on `5cec1f8`; both the dropdown and the parse check are in the code that actually
runs, not only in my branch. No workers to bring back — I had none.

Took `beaKrACr` next on the grounds that it is a hole in a safety path rather than a feature.
The card named a field, `quietAfterARateLimitUntil`, that no longer exists; the hold moved into
`src/limit-hold.ts` in `68cc3cd` and the field is `nothingIsNudgedUntil`. **Check what the code
does now, not what the review saw** — the card was right about the gap and wrong about the name.

The gap was real and slightly worse than written. `case 'rateLimit'` does two things to one
event, and the only test that went through the bus carried an **allowed** snapshot at 88%, so
the refusal branch had never executed in any test. Both halves were covered apart:
`updateFromPush` directly on `RateLimitWatch`, the quiet directly on `TheLimitOnTheFleet`.

Landed `ac1f0cf`. Two things I decided while writing it:

- **Assert the quiet on both sides of `resetsAt`, not as a boolean.** `true` at `resetsAt - 1`
  and `false` at `resetsAt` says *where the deadline came from* — the account's own reset,
  rather than the 5-minute floor. A boolean would have passed on a wrong argument.
- **Do not assert the freeze in the same test.** `stopTheFleetIfALimitSaysSo` is `void`-called
  and sets `holdsUntil` before its first `await`, so it would pass today — and break the day
  someone moves an await earlier. `stop-at-the-limit` covers it deterministically.

Reached `theLimit` through the cast precedent already in `stop-at-the-limit.test.ts` rather
than adding a public accessor: widening the API so a test can see something makes the API lie
about what callers need. But the cast only fetches the object — the assertions call its own
public methods.

## The answer, and why it changed what I wrote rather than what I did

`e4c55abc` came back: keep `claude-opus-4-8`, deliberate. My reading was wrong, and filing it
instead of "fixing" it is the only reason this is a two-minute note rather than a regression.

The interesting part is what the answer left behind. A deliberate choice with no reason given
and nowhere to live: comments are banned, `f23b870` predates the answer, and the value sits
beside a list naming `claude-opus-5` — which is exactly what made it read as stale to me. The
next session reads it the same way and helpfully updates it.

I first made the assertion the record (`c59dda9`). The operator corrected that twice, and both
corrections were right.

**"Засунь это знание в название переменной просто."** Of course. This codebase puts knowledge in
identifiers everywhere — `refuseAWriteGrantNoRoleWillBeGiven`, `theWindowItMeasuredHasSinceRolledOver`
— and my assertion existed only as a way around the comment ban. A test written to carry a fact
that belongs in a name is not a test.

**And then the fact itself, which I did not have:** `claude-opus-4-8` is where classifier
fallback stops. `bus.ts:166` turns a refusal into `retriedOnFallbackModel` with a `fallbackModel`
and `swapsSessionModel`; `supervisor.ts:841` changes the session's model when both are set. There
is nothing beneath this model to swap in, so a session on it stays on it — which is exactly what
the guardian needs while it scrubs after an incident, and what the setup interview needs. Not age,
not cost.

So the constant is `MODEL_NOT_SWAPPED_WHEN_THE_CLASSIFIER_TRIPS` (`72d01ed`) and the test is gone.
Note how much better the second name is than my first attempt, `OLDER_MODEL_WRAPPER_ROLES_ARE_KEPT_ON`:
that one recorded the symptom I had observed, this one records the property that makes the choice
correct. I had asked the right question and still written the answer down wrong, because I filed
it before the reason arrived.

Second time here that "nobody would deliberately do that" was wrong. Worth remembering as a
rate rather than an anecdote.

## Trello #59 (red) — a stopped turn told its reader it had failed

`f19a2f8`. The card's chain: manager interrupts tester directly, qa reads the tester's turn as a
failure and starts it again, and work that was deliberately stopped runs twice. Nobody in that
chain did anything unreasonable — they read what they were given.

This is the same lie I fixed this morning in `9313c4b`, on a different channel. That one taught
the **activity log** not to call a deliberately cut turn a failure. The mark existed and stopped
at the record: `routeReportToItsReader` still wrote `[report from X, failure]`, because it only
ever saw `ok`. Worth remembering as a shape — **fixing how something is recorded is not fixing
how it is reported**, and I had the flag in hand and did not follow it to the second consumer.

`turnsEndedOnPurpose` was a `setOfSids`: it knew a turn had been cut short and could not say more.
Now a `mapBySid<TurnCutShort>` of `{ by, because }`, and `interruptOne` cannot be called without
one — there were exactly two callers and both already knew the answer, so making it required cost
nothing and closes the hole permanently.

**The operator's correction, mid-work: separate an interruption by the operator from one by
another session.** He was right and my first pass was prose — both reasons were strings that
happened to read differently, so any distinction lived in wording a reader had to parse. Now `by`
is a closed kind and `howThatReads` switches over it with no default, so a fourth source cannot
be added without someone deciding how it reads. The two sentences differ because the right
reaction differs: a session that stopped one of its own will say what happens next, so the reader
is told the decision belongs to them; a human may simply have wanted it to stop, and nothing in
the fleet should quietly undo that.

Last piece, and the one that would have made the rest decorative: the **briefing** now tells
sessions to say why when they interrupt. The chain in the card only carries a reason if the
manager supplies one.
