## The panel refactor, in waves — committed, not landed

Operator asked for the refactor over the point fixes, and asked for waves: commit each, push at
the end. Three so far: `38d1bf9`, `25552f3`, `b9cfdf3`. Nothing landed yet.

The case for doing this was that panel behaviour could only be checked by reading it. **That case
is now proven rather than argued: the harness found three real defects in its first hour, and all
three were in code I had read carefully within the last two days.** That is the number to keep.

### Wave 1 — the test surface, and it needed no restructuring at all

The surprise: of 2073 script lines the only top-level statement is `void boot();` on the last one.
`tests/panel-harness.ts` lifts the script out of `app.html`, drops that one call, and runs the rest
in a subprocess. **No stubs were needed** — no `document`, no `fetch` — because nothing else runs
at load. Any of the 128 functions can then be asked a question.

Two defects inside a minute:

- **`findInTree` recursed into `node.reports` unguarded.** One node arriving without the field
  throws `TypeError` out of a function every render path calls, and the panel paints nothing. I had
  read that function twice this week and not seen it.
- **`formatTokens(999999)` read `1000k`** — four digits in front of a unit whose job is three. The
  boundary tested the input against 1000000 instead of testing what the output would say.

And the thing I could only claim in prose yesterday is now a property test: whatever goes through
`renderMarkdown`, no tag it emits carries an attribute.

### Wave 2 — the render functions

A forty-line page stub: `createElement`/`getElementById` returning objects that remember
`className`, `textContent`, `children` and listeners, plus a `press()` that fires them. jsdom was
not an option — `npm install` cannot run in the sandbox, on a cache outside the write list — which
turned out fine: small and honest about modelling structure, not layout.

It covers what I had shipped that morning with no test at all: the collapsed tags. Four claims from
a commit message became assertions, including the one that matters — a frozen session shows its

### Wave 3 — the limit header

"Полоски часто врут", twice. Now assertable: clamping, threshold positions, that 0% is a reading
rather than a missing one, which window is announced as binding.

Writing those found one that **did** lie. `renderLimitGauge` applied the severity only when a
percentage had been measured, so a window with `status: 'rejected'` and `utilizationPercent: null`
— exactly what a push delivers before any poll has measured that window — drew grey, at zero,
labelled "no data". The account had said something; it had said no. Severity now comes from the
status regardless, the reading says "refused", and the colour goes on the value as well as the fill
because a fill zero pixels wide cannot carry one. **No width invented** — a refusal without a
number does not silently become 100%.

## Waves 4-6, and where the refactor ends

`623e5ce`, `9c276ef`, `8000abd`, `de2e538`. Seven commits in all, none landed yet.

**Wave 4 — four ways to be told, one way to be wrong.** `showSession` painted ten things; the
snapshot painted three of them; a background-task event painted a fourth; the transcript had two
more. Which of the ten belonged to the snapshot path had been decided once per field, by whoever
added the field, never as a rule. Both of this week's panel complaints come out of that, plus one
nobody had reported: **a session freezing while you watch showed the new status word and kept the
reason invisible until you reopened the panel.** Now one record, each channel updating only what
it carries, one paint. The transcript stays separate on purpose — it is appended to, and
rebuilding it every second would throw away scroll position and every expanded entry.

**Wave 5 — escaping by construction.** 11 sinks and 19 `escapeHtml` calls became 1 and 3. A tagged
template escapes interpolations; already-built markup carries a symbol and passes through;
`paintInto` is the only line that writes `innerHTML`, and a test asserts both that there is one
and that it is the escaping one.

Two mistakes caught by looking rather than running, both worth keeping: `html` returns an object,
so the old `+` concatenation would have painted `[object Object]`; and `renderLimitGauge` returned
a raw string, which the new sink would have **escaped and shown as markup-as-text** — while the
test calling it directly stayed green, because it never went through the sink.

**And the find of the day: there was already a harness.** `limit-headline.test.ts` built a module
from function sources cut out of `app.html` by name, listed in a `NEEDED` array. That design fails
the moment a function gains a dependency — which is exactly what happened: five tests went red
because `renderLimitGauge` started calling `html`. It is on the shared harness now and forty lines
of extraction machinery are gone. **A partial harness is worse than none: it looks like coverage
and breaks on unrelated edits.**

**Wave 6 — shadows.** 22 globals; most are simply what a single-page app knows and counting those
as defects would have been the wrong kind of tidying. Three were shadows of state that already
existed. Folding the tag expansion into the panel's record does better than delete a variable:
opening another session replaces that object, so the expansion is discarded **by construction**.

## The lesson that repeated three times today

A test that sets up the state it then checks is testing itself. Three times:

1. The background-task test called the store directly; putting the handler back to bypassing the
   store left the suite green. Fixed with an `EventSource` stub so it goes through the real handler.
2. The tag tests called `renderTags` directly and never passed the "is this session on screen"
   guard. Moving them onto `thePanelNowKnows` made all four fail at once — the tell.
3. The gauge test called `renderLimitGauge` directly, so it would not have noticed the sink
   escaping its output.

Every one was found by mutation, not by reading. **Mutation first, belief after.**

## Where it ends, and why not further

The file is **not** split, deliberately. Modules buy isolation for testing; the harness bought that
for one file. Splitting also touches delivery — the server serves one file, `write-guard.ts` names
it, four tests read it by path. Size alone is not a defect, and I said so before starting.

Final: 1 sink, 3 `escapeHtml`, 19 globals, 640 tests. Four real bugs found in code I had read
carefully, all fixed.

## The research round, and the experiment that explained it

Refactor plan exhausted, so: fresh research. Four workers on distinct areas plus me on the
incident machinery. **Of ~25 claims returned, one was true and material.** Every other one I
checked was verifiably false — the guard *does* catch `2>/path`, `integrations.json` *is* denied
by default (`supervisor.ts:403`, a product default and not this fleet's config), a session
*cannot* reach the panel (it listens on 4173; the connection is refused).

The one that was true: `send()` to a parked session was
`void this.unpark(sid).then(() => rec.handle?.send(text))`. The worker reported the missing catch.
The actual defect was the **optional call** — `?.` turns "could not deliver" into "nothing
happened", while `send()` had already returned true and `messageSent` was already on the bus.
Fixed in `652d379`.

The false ones are now a section in RESEARCH so nobody re-derives them.

### Then the experiment, which is the part worth keeping

I did not know whether the method or the model was at fault. So: cleared one worker, retuned it
to **opus**, sent it the **same area and the same task**, with one addition — every finding must
carry a `проверено:` field, the guard can be asked directly via `buildWriteGuard` without running
anything, and *"after checking, none survived"* was named as a correct answer.

Six findings came back. **All six real**, each with a control command showing the guard catches
the equivalent written the expected way. I re-verified three independently and they hold.

So the answer is unambiguous: **it was the model, not the method.** Haiku returns what the code
*looks like*; opus returns what it *does*. The verification requirement helped, but a cheap model
with a verification requirement would simply have verified nothing.

### What it found

- **`git --git-dir <path>` with a space** skipped the entire git branch: only the `=` form was
  matched, so the target stayed at cwd and the path itself read as the subcommand, which is in no
  verb set. Rewrites the refs every worktree shares.
- **`/usr/bin/git`** walked past the git rules *and* the unreadable-program scan at once: the git
  branch looked for a token equal to `git`, the scan took the basename of the path.
- **The stopping-verb test matched after any whitespace**, so any `grep` carrying that word and a
  path from this product was refused as an attempt on the supervisor. **It cost me two turns in
  this very session** — the second time the word was in an `echo` label.
- **`pkill -f node` was allowed**, because the check asked whether the command spelled out
  silicyte or supervisor. The supervisor is a node process.
- **A symlink out of a worktree reaches `<shared>/.git`**: the guard compares paths lexically,
  the OS resolves realpath. Worker demonstrated it on the filesystem and cleaned up after itself.
  **Not fixed** — the sandbox must allow that directory, because committing from a worktree writes
  there.
- **The text fallback for unreadable programs only scans the orchestrator's own files**, so
  `python3 -c` writing into `<shared>/.git` passes while the shell redirect is refused.

Four fixed in `0f2ec5f`, with tests and controls.

### And the claim that was wrong in three documents at once

MAP.md, RESEARCH.md and my own skill all said the sandbox's write list and the guard were "built
from the same paths, so the two cannot disagree". **`write-guard.ts` does not import `sandbox.ts`
at all.** Both start from one `WhereASessionWorks` and arrive at different lists; the sandbox adds
each shared checkout's `.git`, the workspace's `.git` and `tmpdir()`. Three of the findings above
live in exactly that difference. Corrected in `9f73ad5`.

**The lesson under the lesson:** a sentence asserting that two things cannot disagree is the most
dangerous kind to leave unchecked, because it tells every later reader not to look.
